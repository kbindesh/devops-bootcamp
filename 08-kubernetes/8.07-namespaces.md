# Kubernetes Namespaces

In this section, you will learn the following concepts:

- Kubernetes Namespaces
- Listing Namespaces
- Creating Namespaces using both imperative & declarative ways
- Limit Ranges
- Resource Quotas

## 01. What is Kubernetes Namespace?

- A K8s **Namespace** is a logical partition inside a single physical cluster that functions as a "virtual cluster".

- It allows you to group, organize, and isolate resources so multiple teams, projects, or environments (like Dev, Staging, and Production) can safely share the same infrastructure without interfering with one another.

### Advatanges of Namespace

- **Prevent Naming Collisions**
  - Resource names must be unique within a namespace, but not across them.

- **Access Control (RBAC)**
  - Administrators use Kubernetes Role-Based Access Control (RBAC) to restrict user access to specific namespaces.
- **Resource Limits**
  - You can attach a _ResourceQuota_ to a namespace to cap the total amount of CPU, memory, or storage its workloads can consume, preventing a single team from exhausting the cluster's physical resources.

### Default Namespaces

Every new K8s installation automatically creates four built-in namespaces:

1. **default**
   - The standard landing zone for any resource you create if you do not explicitly define a namespace.

2. **kube-system**
   - Reserved strictly for core components managed by the Kubernetes control plane, such as network plug-ins and DNS.
3. **kube-public**
   - Unauthenticated and readable by all users.
   - It is rarely used directly and is kept for cluster discovery data.
4. **kube-node-lease**
   - Holds lease objects tied to node heartbeats, helping the cluster track server availability efficiently.

```bash
# List existing namespaces
kubectl get namespaces
```

### Namespaces - Key Considerations

- **Scope Constraints**
  - Most resources (Pods, Services, Deployments, Secrets) live within a namespace.
  - Some low-level or foundational resources like Nodes, StorageClasses, and PersistentVolumes are cluster-wide and exist outside of any namespace.

- **Cross-Namespace Communication**
  - Namespaces do not provide strict network isolation by default—they provide logical isolation.
  - Pods can still talk across namespaces using a fully qualified domain name (FQDN).

- **No Nesting** - Namespaces cannot be nested inside one another.

## 02. Namespace - kubectl commands

### 2.1 Listing Namespaces

```
kubectl get namespaces
OR
kubectl get ns
```

### 2.2 Create Namespaces (imperative way)

```bash
# Create a dedicated namespace for development environment
kubectl create namespace dev

# Create a dedicated namespace for test environment
kubectl create namespace test

# Create a dedicated namespace for production environment
kubectl create namespace prod

# To check created ns, list all the namespaces
```

### 2.3 Create Namespaces (Declarative way)

- Develop a K8s manifest _dev-namespace.yml_ for creating a Namespace (e.g. development)

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: development
  labels:
    name: development
```

```bash
kubectl apply -f dev-namespace.yml
```

### 2.4 Deploy an Application in custom Namespaces

- To deploy a stateless applicaion in a custom _Namespace_, you can specify _Namespace_ details in two ways:

#### Using `kubectl apply -n` option

```bash
# Deploy nginx app in production namespace using kubectl -n option
kubectl apply -f nginx-deployment.yml -n production
```

#### Using `metadata.namespace` element

```yaml
# Notice metadata.namespace attribute

apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
  namespace: production
  labels:
    app: nginx
```

- Now, deploy an app (e.g. nginx) in _development_ namespaces:

```bash
kubectl apply -f manifests/nginx-deploy-in-dev-ns.yml)
```

### 2.5 List Namespace objects

```bash
# List all common objects in a Namespace
kubectl get all -n <my-namespace>

# List all the Pods from a given Namespace
kubectl get pods -n my-namespace

# List all the Services from a given Namespace
kubectl get svc -n my-namespace

# List objects by label in a Namespace
kubectl get all -n my-namespace -l app=frontend

# Set Default Namespace for kubectl commands
kubectl config set-context --current --namespace=my-namespace
kubectl get pods

[Now, you can just run commands without appending -n or --namespace]
```

## 03. Limit Range

As an Administrator, you might be concerned about making sure that a single object cannot monopolize all available resources within a namespace.

- A **LimitRange** is a policy to constrain the resource allocations (limits and requests) that you can specify for each applicable object kind (such as _Pod_ or _PersistentVolumeClaim_) in a namespace.
- A **LimitRange** provides constraints that can:
  - _Enforce minimum and maximum compute resources usage per Pod or Container in a namespace_.
  - _Enforce minimum and maximum storage request per PersistentVolumeClaim in a namespace_.
  - _Enforce a ratio between request and limit for a resource in a namespace_.
  - _Set default request/limit for compute resources in a namespace and automatically inject them to Containers at runtime_.

### Lab: Create a Namespace and restrict the Pod resource allocation using `LimitRange`

- Develop a manifest _dev-ns-with-limitrange.yml_ for creating a namespace and apply range limit for the same:

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: development
  labels:
    name: development

---
apiVersion: v1
kind: LimitRange
metadata:
  name: dev-limit-range
  namespace: development
spec:
  limits:
    - default: # this section defines default limits
        cpu: "500m" # Default is 1 cpu
        memory: "512Mi"
      defaultRequest: # this section defines default requests
        cpu: "300m"
        memory: "256Mi"
      type: Container
```

- Apply the above configuration:

```bash
kubectl apply -f dev-ns-with-limitrange.yml
```

### Lab: Deploy an Application in the Namespace (where limitRange is set)

- Develop a manifests for deploying an application (e.g. nginx) in the same Namespace (here, development) where we set the limitRange object:

```bash
kubectl apply -f
```

### Lab: Verify the deployed app Pods and it's Resource limits (cpu, memory)

```bash
# List all the pods present in development namespace
kubectl get pods -n development

# List all the limitRanges of development namespace
kubectl get limits -n development

# Describe the limit range to view resource limits for dev Pods
kubectl describe limits dev-limit-range -n development

# Finally, check the Pod resource limits inherited from limitRange
kubectl describe pod $POD_NAME -n development

[Observe the resource limits of the Pod]
```

## 04. Resource Quota

- A Kubernetes ResourceQuota is a cluster-level object that limits aggregate resource consumption (CPU, memory, storage, and object counts) per namespace.

- It acts as a strict budget to prevent any single team or application from consuming excessive shared cluster resources in multi-tenant environments.

### Lab: Create a new `namespace` apply `limit range` and `resource quota`

- Develop a K8s manifest _dev-ns-with-limit-res-quota.yml_ for creating the following resources:
  - **Namespace**: development
  - **LimitRange**: <capacity_for_indivisual_container>
  - **ResourceQuota**: <capacity_allocated_for_namespace>

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: development
  labels:
    name: development

---
apiVersion: v1
kind: LimitRange
metadata:
  name: dev-ns-resource-limit-range
  namespace: development
spec:
  limits:
    - default: # this section defines default limits
        cpu: "500m" # Default is 1 cpu
        memory: "512Mi"
      defaultRequest: # this section defines default requests
        cpu: "300m"
        memory: "256Mi"
      type: Container
---
apiVersion: v1
kind: ResourceQuota
metadata:
  name: dev-ns-resource-quota
  namespace: development
spec:
  hard:
    requests.cpu: "1"
    requests.memory: 1Gi
    limits.cpu: "2"
    limits.memory: 2Gi
    pods: "5"
    configmaps: "5"
    persistentvolumeclaims: "5"
    replicationcontrollers: "5"
    secrets: "5"
    services: "5"
```

- Run the above manifest to create k8s objects:

```bash
kubectl apply -f dev-ns-with-limit-res-quota.yml
```

### Test and describe deployed resources

```bash
# List pods of development namespace
kubectl get pods -n development -w

# View Pod Specification (CPU & Memory)
kubectl get pod $POD_NAME -o yaml -n development

# Get & Describe Limits set
kubectl get limits -n development

kubectl describe limits dev-ns-resource-limit-range -n development

# list & Get Resource Quota
kubectl get quota -n development

kubectl describe quota dev-ns-resource-quota -n development
```
