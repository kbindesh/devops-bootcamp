# Managing Storage in Kubernetes

In this section, we will learn how to manage storage for application workloads. K8s storage mechanism is broadly categorized into following types:

1. **Ephemeral Storage**
   - Storage tied to a Pod's lifecycle

2. **Persistent Storage**

## Manage Ephemeral Storage

- Ephemeral volumes meant for application to hold the data, but they don't really care about data loss in the case that the pod fails or restarts.
- The lifecycle of the ephemeral volume is aligned with the pod lifecycle.
- Mounted storage is usually ephemeral, as it shares the same lifecycle as your containers.
- As soon as the container is stopped or destroyed during the process of restarting the pod, any internal storage is completely removed.

- Kubernetes supports multiple ephemeral storage mechanisms:
  1. **emptyDir** (for intra-pod communication)
  2. **Projected volumes**
  3. **CSI ephemeral volumes**

### Lab: Sidecar in Action: Real-Time Data Sharing with emptyDir Volumes

Let's create a YAML script with an *emptyDir* volume mounted to a pod:

`emptydir-vol-pod.yml`

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: emptydir-vol-pod
spec:
  restartPolicy: Never
  volumes:
  - name: shared-data
    emptyDir: {}
  containers:
  - name: busybox-container
    image: busybox
    command: ["/bin/sh","-c","while true; do sleep 3600; done"]
    volumeMounts:
    - name: shared-data
      mountPath: /tmp/data
  - name: nginx-container
    image: nginx
    volumeMounts:
    - name: shared-data
      mountPath: /data
```

To use the shared memory option, we just need to add medium: Memory to the emptyDir section, as follows:

```yaml
volumes:
- name: shared-data
  emptyDir:
    medium: Memory
```

- Note that memory-based emptyDir counts toward the container's memory limit.

To verify if it works, let's create a pod with two containers and then write a file using one container and read it using the other container:

```bash
# Deploy the above created manifest
kubectl create -f emptydir-vol-pod.yml

# List containers belongs to above Pod
kubectl get pod emptydir-vol-pod -o json | jq .spec.containers

# Create a file in /tmp/data directory of busybox-container
kubectl exec -it emptydir-vol-pod -c busybox-container -- touch /tmp/data/File.txt

# Now, list the created file in /data directory of the nginx-container
kubectl exec -it emptydir-vol-pod -c nginx-container -- ls /data
```

## Manage Persistent Storage (Volumes)

Persistent storage decouples data from the Pod lifecycle using three core Kubernetes abstractions:

1. **StorageClass (SC)**
   - Defines the underlying storage provider (e.g., AWS EBS, GCP Disk, local disk) and provisioning parameters.

2. **PersistentVolumeClaim (PVC)**
   - A user or developer request for storage specifying size and access modes.

3. **PersistentVolume (PV)**
   - The actual piece of storage in the cluster, provisioned dynamically via a StorageClass or statically by an administrator.

### Lab:  Dynamic Provisioning of Persistent Volume with PVC and mounting on Pods (minikube)

First, define a claim requesting storage. Kubernetes provisions a matching *PV* automatically using a *StorageClass*.

- Minikube includes a built-in storage provisioner plugin. 
- To make the dynamic provisioning lab work seamlessly on Minikube, you only need to ensure your YAML points to Minikube's specific *storage class* name.

```bash
# Verify Minikube's Default StorageClass
kubectl get storageclass

# You will see an output similar to this:
NAME                 PROVISIONER                RECLAIMPOLICY   VOLUMEBINDINGMODE   ALLOWVOLUMEEXPANSION   AGE
standard (default)   k8s.io/minikube-hostpath   Delete          Immediate           false                  5m
```

- Now, let's create YAML manifests for Persistent Volume Claim (PVC) and Pod:

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes:
    - ReadWriteOnce  # Mounted as read-write by a single node
  resources:
    requests:
      storage: 5Gi
  storageClassName: standard  # Refers to your cluster's provisioner
---
apiVersion: v1
kind: Pod
metadata:
  name: persistent-demo-pod
spec:
  containers:
  - name: database-container
    image: postgres:latest
    volumeMounts:
    - mountPath: /var/lib/postgresql/data
      name: persistent-storage
  volumes:
  - name: persistent-storage
    persistentVolumeClaim:
      claimName: my-pvc
```
