# Liveness, Readiness and Startup Probes

## Liveness Probe

- A Liveness Probe in Kubernetes is a diagnostic mechanism used by the kubelet to determine if a container inside a Pod is still running properly.

- If an application gets stuck in an unrecoverable state (such as a deadlock or an infinite loop), the liveness probe fails, and Kubernetes automatically kills and restarts the container to restore its health.

- Probes are defined inside the _Pod_ or _Deployment_ specification under the `spec.containers` field.

### Types of Liveness Probes

Kubernetes supports four ways to check a container's health:

- **HTTP GET**: Sends an HTTP request to an endpoint (e.g., /healthz). A status code between 200 and 399 indicates success.

- **Exec Command**: Runs a specific command inside the container. An exit code of 0 means success; non-zero means failure.
- **TCP Socket**: Attempts to open a TCP connection on a designated port. If the port is open, the check passes.
- **gRPC**: Performs a native gRPC health check for gRPC-supported applications.

### Lab: Deploy an App with Liveness Probe

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: liveness-example
spec:
  containers:
    - name: my-app
      image: nginx:latest
      ports:
        - containerPort: 80
      livenessProbe:
        httpGet:
          path: /healthz
          port: 80
        initialDelaySeconds: 15
        periodSeconds: 10
        timeoutSeconds: 2
        successThreshold: 1
        failureThreshold: 3
```

Key Parameter details:

- **initialDelaySeconds**
  - Time to wait after the container starts before running the first probe.
- **periodSeconds**
  - Frequency of the health check execution.
- **timeoutSeconds**
  - Maximum duration allowed for the probe to respond before timing out
- **successThreshold**
  - Minimum consecutive successes required to mark an unhealthy container as healthy.
- **failureThreshold**
  - Number of consecutive failures allowed before Kubernetes forces a container restart.

## Readiness Probe

- A Readiness Probe is a diagnostic mechanism used by the kubelet to determine if a container is fully prepared to accept incoming network traffic.

- Unlike a _liveness probe_, which restarts a failing container, a _readiness probe_ failure simply stops routing traffic to the container.
- The Pod remains alive, but Kubernetes removes its IP address from all associated Service endpoints.
