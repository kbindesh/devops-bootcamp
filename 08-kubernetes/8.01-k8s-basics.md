## 01. What is Kubernetes?

- `Kubernetes` is a platform to orchestrate the deployment, scaling, and management of container-based applications.
- The correct pronunciation of Kubernetes is **Koo-ber-netties** or **Koo-ber-nay-tace**.

- Kubernetes was a Google project, but joined the _Cloud Native Computing Foundation (CNCF)_ and is now the de facto standard in the space of container-based applications.
- The core functionality is scheduling workloads in containers across your infrastructure.
- Some of the other kubernetes capabilites are as follows:
  - Providing authentication and authorization

  - Debugging applications

  - Accessing and ingesting logs

  - Rolling updates

  - Using Cluster Autoscaling

  - Using the Horizontal Pod Autoscaler

  - Replicating application instances

  - Checking application health and readiness

  - Monitoring resources

  - Balancing loads

  - Naming and service discovery

  - Distributing secrets

  - Mounting storage systems

## 02. Introducing Container Orchestration

- The primary responsibility of Kubernetes is container orchestration.

- K8s make sure that all the containers that execute various workloads are scheduled to run on physical or virtual machines.
- Kubernetes must keep an eye on all running containers and replace dead, unresponsive, or unhealthy containers.
- In order to run workloads, you need:
  - Physical machines

  - Virtual machines (optional)
  - Local persistent disks
  - Shared persistent disks
  - Networking resources

- Kubernetes can be deployed on a _bare-metal cluster_ or on a _cluster of virtual machines_.
- Kubernetes in turn can orchestrate the containers it manages directly on bare-metal or on virtual machines.

### 2.1 Advantages of Containers

Here are some of the benefits of containers compared to more conventional software packaging, shipping, deployment and ops models:

- Agile application creation and deployment

- Continuous development, integration, and deployment
- Development and operations separation of concerns
- Environmental consistency across development, testing, staging, and production
- Cloud and OS distribution portability
- Application-centric management
- Resource isolation
- Resource utilization

### 2.2 Microservices & Containers in the Cloud

- Microservices are the widely used architecture for modern large-scale systems.

- The primary idea with microservice is to break down the system into small services with well-defined responsibilities that manage their own data and communicate with other microservices through well-defined APIs.
- Containers are ideal to package microservices because, while providing isolation to the microservice.
- Containers are very lightweight and you do not incur a lot of overhead when deploying many microservices, as you do with virtual machines.
- All major cloud providers, such as AWS, Google Cloud Platform, and Microsoft Azure, provide container hosting services, like:
  - Amazon Elastic Container Service (ECS)

  - Amazon Elastic Kubernetes Service (EKS)
  - Azure Kubernetes Services (AKS)
  - Azure Container Instances
  - Azure Container Apps
  - Google Kubernetes Engine (GKE)
  - DigitalOcean DKE
  - Rackspace KaaS

## 03. Understanding kubernetes key concepts

### 3.1 Kubernetes Architecture

- Kubernetes architecture follows a client-server model split into a `Control Plane` (the brain) and `Worker Nodes` (the muscle) that together form a unified cluster.

- This structure ensures the "actual state" of your running applications always matches the "desired state" you define through configuration files

| Layer         | Key Responsibility                                            | Primary Components                               |
| ------------- | ------------------------------------------------------------- | ------------------------------------------------ |
| Control Plane | Makes global decisions, schedules workloads, monitors status. | API Server, etcd, Scheduler, Controller Manager. |
| Worker Nodes  | Runs the actual containerized applications inside Pods.       | Kubelet, Kube-proxy, Container Runtime.          |

#### 3.1.1 The Control Plane (Master Components)

The ⁠Kubernetes Control Plane manages the overall health, direction, and configuration of the cluster.

- `kube-apiserver`
  - The front door to Kubernetes. It exposes the HTTP REST API, handles authentication/authorization, and processes incoming requests from tools like kubectl.

- `etcd`
  - A highly-available, distributed key-value store. It serves as the single source of truth, holding all configuration data and cluster states.
- `kube-scheduler`
  - The matchmaker. It watches for newly created Pods and assigns them to specific worker nodes based on resource limits, policies, and node capacity

- `kube-controller-manager`
  - The enforcer. It runs background control loops (like the Node Controller and Replication Controller) to continuously align the cluster's actual state with your target settings
- `cloud-controller-manager`
  - The cloud translator. It integrates your cluster with your chosen cloud provider's API to manage load balancers, storage volumes, and cloud-native routes

#### 3.1.2 Worker Nodes (Data Plane Components)

Worker nodes provide the compute environment. They require three core processes to communicate with the master and manage containers:

- `kubelet`
  - The _node captain_.
  - This agent runs on every node to guarantee that containers are running inside their respective Pods exactly as directed by the Control Plane.

- `kube-proxy`
  - The _traffic controller_.
  - A network proxy that maintains network rules on the host machine, enabling traffic to reach your Pods from inside or outside the cluster.
- `Container Runtime`
  - The _execution engine_.
  - Software (such as docker or containerd or CRI-O) explicitly responsible for pulling container images from a registry and running them.

## 04. Kubernetes Container Runtimes

- Kubernetes originally only supported Docker as a container runtime engine. However, that is no longer the case.
- Kubernetes now supports any runtime that implements the CRI interface.
  - **Docker**
  - **containerd**
  - **CRI-O**

## 06. The Kubernetes APIs

- The API provides a comprehensive view of what you can do with the system as a user.

- You can generate the full list of all API resources supported by your k8s cluster by running the command `kubectl api-resources` in your terminal.

- Kubernetes exposes several sets of REST APIs for different purposes and audiences via API groups.

- The native, core API resources built into Kubernetes are organized below by their functional **API Groups**.

### 6.1 Core API Group (Group: "", Version: v1)

These are the foundational bricks of Kubernetes. They do not require an explicit group name prefix in their apiVersion configuration.

- pods (po)
  - The smallest running unit containing your containers.
- services (svc)
  - Exposes your application pods to network traffic.

- namespaces (ns)
  - Isolates resources into virtual sub-clusters.

- nodes (no)
  - The physical or virtual worker machines in the cluster.
- configmaps (cm)
  - Stores non-sensitive configuration data.secrets – Stores sensitive data like tokens, passwords, and keys.
- persistentvolumeclaims (pvc)
  - Requests storage resources.
- persistentvolumes (pv)
  - Low-level cluster storage provisions.
- endpoints (ep)
  - Tracks the IP addresses of pods linked to a service.
- serviceaccounts (sa)
  - Provides identities for processes running in your pods.
- replicationcontrollers (rc)
  - Older mechanism to scale pods.
- events (ev)
  - Logs cluster status changes or errors.

### 6.2 Workload Management Group (apps/v1)

These resources manage lifecycle, scaling, and the state of your application containers.

- deployments (deploy)
  - Manages stateless application rollouts and updates

- statefulsets (sts)
  - Manages stateful applications requiring unique identities.
- daemonsets (ds)
  - Ensures a copy of a pod runs on every targeted worker node.
- replicasets (rs)
  - Maintains a stable set of identical backup pods running at any given time.

### 6.3 Batch Workloads Group (batch/v1)

Designed for short-lived, completion-oriented computing tasks rather than continuous services

- jobs
  - Runs a set batch of containers to successful completion.

- cronjobs (cj)
  - Automates and schedules jobs using standard cron syntax.

### 6.4 Networking Group (networking.k8s.io/v1)

Controls how traffic flows in, out, and across your running workloads.

- ingresses (ing)
  - Routes external HTTP/HTTPS traffic to internal services.

- ingressclasses
  - Configures shared controller settings for your ingresses.
- networkpolicies (netpol)
  - Defines explicit firewall rules governing communication between pods.

### 6.5 Storage Group (storage.k8s.io/v1)

Coordinates interaction with external storage providers

- storageclasses (sc)
  - Dynamically provisions storage backends based on defined tier rules.

- csidrivers
  - Registers Container Storage Interface (CSI) drivers inside the cluster.
- csinodes
  - Maps node identities directly to localized cloud-storage volumes.

### 6.6 Security & Access Control (RBAC) Group

Governs fine-grained cluster permissions for both human users and applications.

- roles
  - Lists localized permissions within a distinct namespace.
- rolebindings
  - Grants localized role permissions to specific users or ServiceAccounts.
- clusterroles
  - Lists wide-ranging permissions across the entire cluster.
- clusterrolebindings
  - Grants wide cluster-role access to specific users globally.

### 6.7 Useful Commands to Filter and Explore

```
# List API resources with version, NS scope and supported actions
kubectl api-resources -o wide

# List only namespaced API Resources
kubectl api-resources --namespaced=true

# List cluster-scoped/non-namespaced resources
kubectl api-resources --namespaced=false
```
