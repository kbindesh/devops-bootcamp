## 02. Lab: Integrate GitHub with local system (git)

### 2.1 Prerequisites

- Git
  - Before connecting to GitHub, you need the Git command-line tool installed locally on you Windows/Linux/MacOS machine.

### 2.2 Configure Your Global Git Identity

- Set your name and email address.
- Git attaches this information to every code change (commit) you make so others know who wrote the code.

- Launch terminal and run the following commands:

```bash
git config --global user.name "Your Name"

git config --global user.email "your_email@example.com"
```

📌 Best Practice - Use the exact same email address you used to sign up for your GitHub account so your commits link correctly to your online profile.

### 2.3 Set Up Secure SSH Authentication (Recommended)

You can use Personal Access Tokens (PATs) or SSH key based authentication which are the modern industry standard because they are tied to your specific machine and never expire.

- Launch terminal and run the following command:

```bash
# Generate a new SSH key
ssh-keygen -t ed25519 -C "your_email@example.com"
```

- Copy the public SSH key (located in your host directory/folder of your system) to your clipboard and upload it to your GitHub account.
  - Sign-in to you [GitHub](https://github.com) Account.
  - Click the **New SSH key** button &rarr; Give it a title (e.g., "My Windows Laptop").
  - Paste your copied key into the **Key** text field and click **Add SSH** key.

### 2.4 Test the connection

Run the following command on your local system's terminal:

```bash
ssh -T git@github.com

# If successful, you will see a message like: "Hi {username}! You've successfully authenticated..."
```

## 03. Lab: Initialize a Local Project and Push it to GitHub

### Prerequisites

- Visual Studio Code (IDE)
- Git

### 3.1 Verify Global Git Identity

Before creating commits, ensure Git knows who you are. In production environments, commit metadata is used for auditing and compliance.

1. Open PowerShell or Git Bash &rarr; Set your global name and work email (if not already configured):

```bash
# Check git config
git config -l


# Set the global name and work email
git config --global user.name "Your Full Name"
git config --global user.email "your.name@company.com"
```

- (Optional) Set main as the default branch name for all new repositories:

```bash
git config --global init.defaultBranch main
```

- Verify your settings

```bash
git config --list --global
OR
git config -l
```

### 3.2 Create and Initialize the Local Project

Create a dedicated workspace folder/directory and initialize Git tracking inside it.

- Create a new project folder and navigate into it:

```bash
mkdir C:\Projects\devops-demo-app

cd C:\Projects\devops-demo-app

# Open the folder in VS Code
code .
```

- Initialize the local Git repository:

```bash
git init

# Expected Output: Initialized empty Git repository in C:/Projects/devops-demo-app/.git/
```

### 3.3 Add Production Baseline Files

Never push raw code without a `.gitignore` file (to prevent secrets or build artifacts from leaking) and a `README.md` (for documentation).

1. Create a .gitignore file to exclude environment files and logs

2. Create a README.md file and following content to it:

   ```
   # DevOps Demo App

   ## Production-ready repository initialized via SSH
   ```

- Create a sample Python application script, say `app.py` in the root of the project folder:

  ```py
  print('Hello, Production DevOps!')
  ```

### 3.4 Stage and Commit Your Changes

Move your files through Git's staging area and record your first immutable snapshot.

```bash
# Check the status of your working dir
git status

# Stage all files for commit
git add .

# Commit the staged files with a clear, descriptive message
git commit -m "Initial project structure with gitignore and readme"

# Verify the commit history
git log
OR
git log --oneline
```

### 3.5 Create a Remote Repository on GitHub

Create an empty container on GitHub to receive your local code.

- Log in to GitHub and click the **+** icon in the top-right corner &rarr; **New repository**.
- Enter the following details:
  - **Repository name**: devops-demo-app
  - **Description**
  - **Visibility**: Private (recommended default for enterprise/production code)
  - Click **Create repository**

> [!IMPORTANT]
> Leave _Add a README file_, _Add .gitignore_, and _Choose a license_ **unchecked**. Initializing these on GitHub creates a conflicting commit history.

- On the quick setup screen, ensure SSH is selected and copy the repository URL (e.g., git@github.com:<your-username>/devops-demo-app.git).

### 3.6 Link Remote and Push Code

Connect your local repository to GitHub and push your main branch upstream.

```bash
# Add the remote repository alias named "origin"
git remote add origin git@github.com:<your-username>/devops-demo-app.git

# Verify the remote URL is mapped correctly
git remote -v

# Push your local main branch to GitHub and set it as the upstream tracking branch (-u)
git push -u origin main
```

### 3.7 Lab Verification

1. Refresh your `devops-demo-app` GitHub repository page in your web browser.

2. Confirm that README.md, .gitignore, and app.py are visible.

3. Confirm that future pushes only require running git push without extra arguments.
