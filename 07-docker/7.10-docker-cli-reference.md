# Docker CLI Reference

- The Docker Command Line Interface (CLI) is organized into a clean, predictable structure.

- Modern Docker uses a _Management Command + Sub-command_ pattern.
- Understanding this hierarchy allows you to navigate and use any Docker command without memorizing them all.

## Step-01: Understand the Command Anatomy

- Every standard Docker command follows a predictable, modular structure.

- A standard Docker command is broken down into four distinct parts:

```bash
docker  [management-object]  [sub-command]  -[flags]  [arguments]

# docker: The docker client that talks to the Docker daemon

# management-object: What you want to interact with? e.g. image, container, network, volume

# sub-command (action): What you want to do? e.g. run, start, stop, rm

# The Options & Arguments: How and where you do it? e.g. -d, --name
```

#### Example - Docker CLI Command

```bash
docker container run -d --name $CONTAINER_NAME $IMAGE_NAME
```
