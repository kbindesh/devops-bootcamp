# Docker Swarm Mode

## 01. Swarm - Overview

- Docker Swarm is an integrated, native container orchestration feature built directly into the Docker Engine.

- It allows you to connect multiple physical or virtual machines running Docker into a single, cohesive virtual Docker host cluster called a "swarm".

## 02. Swarm - Core Architecture & Nodes

- **Swarm Manager**
  - The central brain of the swarm cluster.
  - It handles cluster state, schedules services, and processes API requests.
  - Manager nodes use the Raft consensus algorithm to maintain a consistent internal state.

- **Worker Node**
  - Worker Node is a physical machine or virtual machine (VM) dedicated to running your containerized applications and workloads.
  - It receives and executes tasks assigned by the manager nodes.
  - Workers report their state back to the managers.
- **Node Role Switching**
  - You can promote a worker to a manager or demote a manager to a worker dynamically using standard CLI commands.

## 03. Swarm - Services, Tasks, and Replicas

- Service
  - The definition of the work to be executed on the cluster.
  - You define the container image, ports, environment variables, and desired state (e.g., "run 5 instances of Nginx").

- Task
  - An atomic scheduling unit.
  - A task carries a Docker container and the command to run inside it.
  - When you scale a service, the manager assigns more tasks to worker nodes.
- Replicated vs. Global
  - Replicated services run a specified number of identical tasks across the cluster.
  - Global services run one task on every single available node in the swarm.

## 04. Networking in Swarm

- **Overlay Network**
  - Connects multiple Docker daemons together, enabling containers on different physical or virtual hosts to communicate securely without routing configuration.Ingress
- **Routing Mesh**
  - Automatically routes incoming requests for a published service port from any cluster node to an active task running that service, even if no container is running on the node you hit.
- **Docker_gwbridge**
  - A bridge network that connects the overlay networks to an individual node's physical network for outward routing.

## 05. Secrets and Configuration Management

- **Docker Secrets**
  - Securely store sensitive data (like passwords, SSH keys, SSL certificates) without hardcoding them into images or environment variables.
  - Secrets are encrypted in transit and at rest, and only mounted into containers that need them.

- **Docker Configs**
  - Non-sensitive configuration data (like JSON configuration files) managed and distributed across the swarm similarly to secrets, but stored as plain text.
