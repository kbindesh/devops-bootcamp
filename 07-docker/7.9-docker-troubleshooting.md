# Troubleshooting Docker

- To effectively troubleshoot Docker, you need to know how to isolate issues across containers, networks, volumes, and system resources.
- Follow this practical, command-focused guide to diagnose and resolve the most common Docker issues.

## 01. Diagnose Containers & Check Logs

- To diagnose containers and check logs in Docker, use the `docker ps`, `docker logs`, and `docker exec` commands.
- Docker routes your application's standard output (stdout) and error (stderr) streams directly into its logging framework.

- The following step-by-step example walks through identifying a container, investigating its logs, and jumping inside to fix a problem:

### 1.1 Locate the Target Container (container status)

Find the container you want to troubleshoot by retrieving its ID or custom name:

```bash
# List all the "running" Containers
docker container ls
OR
docker ps

# List all the Containers
docker container ls -a
OR
docker ps -a
```

### 1.2 Check the Container Logs (view & stream logs)

Use the docker logs command to inspect what is happening inside the application:

```bash
# View all historical logs of the Container
docker logs $CONTAINER_NAME

# Stream logs in real-time (live mode)
docker logs -f $CONTAINER_NAME

# Check the last N lines of the logs
docker logs --tail 10 $CONTAINER_NAME

# Filter Container logs by time | Isolate entries to a specific window e.g. last 10 min
docker logs --since 10m $CONTAINER_NAME

# Include timestamps | Add exact execution times to your logs to map errors to external events
docker logs -t $CONTAINER_NAME
```

### 1.3 Diagnose Deeply (advanced troubleshooting) | inspect

If the log entries do not reveal the root cause, look at the container's environment and internal file structure.

#### Inspect Container Metadata

- View the low-level system configuration, IP addresses, volume mounts, and health status in JSON format

```bash
docker inspect $CONTAINER_NAME
```

#### Monitor Live Resource Usage`

- Check if the container is crashing due to a memory leak or CPU spike

```bash
docker stats $CONTAINER_NAME
```

#### Open an Interactive Terminal Inside the Container

- If the container is still running, open an internal shell (bash or sh) to browse files, verify system paths, or check internal configuration variables:

```bash
docker exec -it $CONTAINER_NAME bash
```

- Once inside the container, you can run standard Linux diagnostics like `cat /etc/nginx/nginx.conf`.
- Type _exit_ to return to your docker host terminal.

## 02. Interactive Debugging Inside a Container

If the logs aren't enough, drop into a live shell inside the container to test network paths or file systems:

1. **Shell into a running container**

   ```bash
   docker exec -it <container_name> /bin/bash`

   # or use sh instead of "/bin/bash" if "bash" isn't installed)
   ```

2. **Debug a crashing container**
   - If the container exits immediately, override its entrypoint to keep it open:

   ```bash
   docker run -it --entrypoint /bin/sh $IMAGE_NAME
   ```

## 03. Troubleshoot Network & Port Conflicts

Network misconfigurations often cause "connection refused" or binding failures.

### 3.1 Identify the Error

- When a port conflict happens, Docker will throw an error during `docker run` or `docker compose up`:

```bash
Error response from daemon: Ports are not available: exposing port TCP 0.0.0.0:8080 -> 0.0.0.0:0: listen tcp 0.0.0.0:8080: bind: address already in use
```

### 3.2 Find which process is using the Port?

- Run a command on your host machine to find the _Process ID (PID)_ occupying that port (e.g., port 8080)

```bash
# On Linux or MacOS
sudo lsof -i :8080
OR
sudo netstat -tulnp | grep :8080

# On Windows
Get-NetTCPConnection -LocalPort 8080 | Format-List
```

### 3.3 Analyze the Output

- The `lsof` command will output something like this:

```bash
COMMAND   PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
nginx    1425 root    6u  IPv4  28341      0t0  TCP *:http-alt (LISTEN)
```

- This tells you that a local instance of nginx with `PID` 1425 is already using port 8080.

### 3.4 Resolve Port Conflicts

#### Method-A: Change the Docker Port Mapping (Recommended)

- You do not have to stop your host application.
- Change the Host Port (the first number) in your Docker command to a free port like 8081.
- Keep the Container Port (the second number) the same:

```bash
docker run -d -p 8081:8080 my_application
```

#### Method-B: Free Up the Port on the Host

- If the blocking process is an old zombie container or an unnecessary service, kill it

- If it is another Docker container:

```bash
# Find the container ID using that port
docker ps

# Remove the container
docker rm -f <container_id>
```

- If it is a local host process (PID 1425 from previous step):

```bash
sudo kill -9 1425
```

### 3.5 Diagnose & Fix Network Conflicts

- Sometimes, Docker's internal virtual networks overlap with your company's physical Wi-Fi or Office VPN subnets, causing you to lose internet access inside containers.

```bash
# View existing Docker networks
docker network ls

# Inspect a network for Subnet overlaps | Check the IP range allocated to a specific network
docker network inspect bridge

# Look for the Subnet key in the JSON output (e.g., "Subnet": "172.17.0.0/16").
# If this matches your local office network pool, routing will fail.
```

- Fix Network Overlaps via `daemon.json`
  - To permanently change Docker's default network pool to avoid your local network range, edit or create `/etc/docker/daemon.json` on Linux (or use the Docker Desktop Settings -> Docker Engine tab):

  ```json
  {
    "default-address-pools": [
      {
        "base": "192.168.100.0/20",
        "size": 24
      }
    ]
  }
  ```

  - Restart Docker service to apply the changes:

  ```bash
  sudo systemctl restart docker
  ```

## 04. Resolve Storage & Volume Issues

- To fix Docker storage and volume issues, you must identify whether your host hard drive is completely full, _or_ if your container is reading and writing to the wrong directory path.

- Docker storage issues generally fall into two categories:
  1. **Disk space exhaustion** (caused by dangling layers, old images, and logs)
  2. **Volume mount failures** (caused by incorrect paths or permissions).

### 4.1 Diagnose & Fix "No Space Left on Device"

If your host machine runs out of disk space, Docker containers will crash, fail to write databases, or refuse to start.

```bash
# Check Docker Disk Usage | Checks how much space is consumed by containers, images, volumes, and build caches
docker system df
```

#### Clean Up the garbage (purge)

- To instantly reclaim gigabytes of disk space, delete all stopped containers, unused networks, dangling images, and build caches

```bash
docker system prune -a --volumes
```

> [!WARNING]
> The `--volumes` flag deletes anonymous volumes that are not attached to any running container. Ensure your database data is safely backed up or explicitly named.)

### 4.2 Diagnose & Fix "Volume Mount" Issues

Volume issues typically surface when a container starts up but cannot find its files, or crashes with a Permission Denied error.

#### The "Empty Directory" or "Wrong Path" Conflict

- _Problem scenario_
  - You launch a database container, save data, restart it, and all your data disappears.
- _Explaination_
  - This happens because the data was written to the container's temporary layer, not a persistent host volume.

```bash
# Incorrect Syntax (relative/vague path)
docker run -d -v ./mydata:/var/lib/mysql mysql:latest

# Correct Syntax (absolute path)
docker run -d -v /home/user/apps/mysql_data:/var/lib/mysql mysql:latest
```

#### The "Permission Denied" Conflict

- _Problem scenario_
  - The container starts up, but its internal application crashes because it cannot write data to your host folder.
- _Explanation_
  - This occurs because the User ID (UID) inside the container does not match the UID of the folder owner on the host.

- _How to Fix?_

```bash
# Option A: Change ownership to match the container's expected user
sudo chown -R 1000:1000 /home/user/apps/mysql_data

# Option B: Give read/write access to everyone (Quick fix for local dev)
chmod -R 777 /home/user/apps/mysql_data
```
