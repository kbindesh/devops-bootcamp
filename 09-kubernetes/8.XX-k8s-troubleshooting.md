# Kubernetes Troubleshooting Framework

## Application & Pod Failures

- As a Kubernetes trainer, teaching application and pod troubleshooting requires a systematic approach. 
- When a pod fails, the golden rule is *Observation before Action* before editing manifests, always check: 
  - kubectl get pods
  - kubectl describe pod <name>
  - kubectl logs <name> --previous 
  
### CrashLoopBackOff (Application Crash on Startup)

- **What it means?**
  - The container starts up, crashes with a non-zero exit code, and Kubernetes restarts it repeatedly, increasing the delay (exponential backoff) between attempts.

- **Example Error Message**
  ```
  Last State: Terminated
    Reason: Error
    Exit Code: 1
    Started: Fri, 30 Oct 2026 12:00:00 +0100
    Finished: Fri, 30 Oct 2026 12:00:01 +0100
  Back-off restarting failed container
  ```
- **Root Cause**
  - Unhandled application exception, missing database connection string, or bad entrypoint argument.

- **How to Fix?**
  - Inspect the logs of the crashed instance: `kubectl logs <pod-name> --previous`.
  - Fix the missing configuration or code bug (e.g., inject the missing DB_HOST environment variable via ConfigMaps or Secrets).

### OOMKilled (Out of Memory - Exit Code 137)

- **What it means?**
  - The container exceeded its memory limit, and the Linux kernel terminated the process immediately via SIGKILL.

- **Example Error Message / Event**
  ```
  Last State: Terminated
  Reason: OOMKilled
  Exit Code: 137
  ```

- **Root Cause**
  - Memory leak in the application, a traffic spike, or memory limits set too low for the JVM/Node.js/Go runtime heap.
- **How to Fix?**
  - Verify termination reason via `kubectl describe pod <pod-name>`
  - Increase the container memory limits and requests in the deployment YAML, and configure container-aware heap flags (e.g., -XX:MaxRAMPercentage for Java).
  - Monitor usage trends using tools like *Prometheus* or *Fairwinds Goldilocks*.

### ImagePullBackOff / ErrImagePull

- **What it means?**
  - The kubelet is unable to download the container image from the registry.
- **Example Error Message / Event**
  ```
  Events:
  Type     Reason     Age                From               Message
  Warning  Failed     12s (x3 over 36s)  kubelet            Failed to pull image "myrepo/myapp:v99": rpc error: code = Unknown desc = Error response from manager: manifest for myrepo/myapp:v99 not found
  ```
- Root Cause
  - Typo in the image tag/name, private registry lacking an imagePullSecrets configuration, or network blockage.

- **How to Fix?**
  - Check the exact image name and tag in your deployment manifest against your container registry.
  - If using a private registry (e.g., AWS ECR, Docker Hub, Harbor), attach or renew the imagePullSecrets.

### CreateContainerConfigError

- What it means
  - Kubernetes cannot create the container because an referenced configuration resource is missing or malformed.

- Example Error Message / Event
  ```
  Events:
  Type     Reason       Age   From               Message
  Warning  Failed       10s   kubelet            Error: secret "app-secret" not found
  ```

- Root Cause
  - A *ConfigMap* or *Secret* declared in envFrom, env, or volume mounts does not exist in the same namespace.

- How to Fix?
  - Create the missing ConfigMap or Secret via `kubectl apply -f ...`.
  - Verify spelling and namespace alignment between the workload manifest and the configuration object.
