# HashiCorp Configuration Language (HCL)

- The HashiCorp Configuration Language (HCL) is a declarative, human-readable language designed specifically for provisioning infrastructure with Terraform.

## Syntax Anatomy (Blocks, Arguments, and Expressions)

- Every HCL file is a collection of blocks that contain arguments and expressions.

```bash
Block Type  Block Label   Block Label
   |             |             |
 ______   _____________   ___________
|      | |             | |           |
resource "aws_instance"  "web_server" {

  # Argument  =  Expression (Literal string)
  ami         = "ami-0c55b159cbfafe1f0"

  # Argument  =  Expression (Reference to a variable)
  instance_type = "t3.micro"
}
```

## Terraform Variables - Data Types and Collection

- Terraform uses a specialized type system to ensure that input variables and resource arguments are structured and validated correctly.

- These types are divided into three primary categories:
  1. Primitive - string, number, bool
  2. Collection - list, set, map
  3. Structural types - object, tuple

### Primitive Data Types

Primitive types represent single, simple values that cannot be broken down further.

- **string**
  - A sequence of Unicode characters (e.g., "us-east-1").

  ```bash
  variable "instance_name" {
    type    = string
    default = "web-server"
  }
  ```

- **number**
  - Represents both integers and floating-point values (e.g., 10, 6.28).

  ```bash
  variable "instance_count" {
    type    = number
    default = 3
  }
  ```

- **bool**
  - A boolean value that can only be true or false.

  ```bash
  variable "enable_monitoring" {
    type    = bool
    default = true
  }
  ```

### Collection Data Types

Collection types group multiple values of the same underlying type into a single value.

- **list(...)**
  - An ordered sequence of values (e.g., list(string) for ["a", "b"]).

  ```bash
  variable "availability_zones" {
    type    = list(string)
    default = ["us-east-1a", "us-east-1b"]
  }
  ```

- **set(...)**
  - An unordered collection of unique values where duplicates are automatically removed.

  ```bash
  variable "unique_ips" {
    type    = set(string)
    default = ["10.0.0.1", "10.0.0.2", "10.0.0.1"] # Resolves to two unique IPs
  }
  ```

- **map(...)**
  - A collection of key-value pairs where all keys are strings and all values share the same type (e.g., map(string)).

  ```bash
  variable "server_config" {
    type = object({
      name         = string
      port         = number
      is_encrypted = bool
    })
    default = {
      name         = "app-server"
      port         = 8080
      is_encrypted = false
    }
  }
  ```

### Structural Types

Structural types allow you to group values of different types together in a predefined structure.

- **object({...})**
  - A complex structure with named attributes, each with its own specific type (e.g., object({ name=string, age=number })).

  ```bash
  variable "user" {
    type = object({ name = string, age = number })
    default = { name = "Alice", age = 30 }
  }
  ```

- **tuple([...])**
  - A fixed-length, ordered sequence where each element can have a different type (e.g., tuple([string, number, bool])).

  ```bash
  variable "mixed_data" {
    type    = tuple([string, number, bool])
    default = ["db-instance", 5432, true]
  }
  ```

### Special Data Types

- **any**
  - A placeholder that allows any data type. Terraform will attempt to infer the actual type based on the value provided.
- **null**
  - A special value representing the absence of a value. If an argument is set to null, Terraform treats it as if the argument was omitted.

## String Interpolation

- String interpolation allows you to insert dynamic values into a string using the syntax ${expression}.

- Terraform evaluates the expression inside the braces and converts it to a string

```bash
# Combine a static name with a variable value
name = "server-${var.environment}"  # Result: "server-prod"

# Reference a property from another infrastructure resource
comment = "Managed by instance ${aws_instance.web.id}"

# Format data inside the string
bucket_name = "company-${lower(var.department)}-bucket"

# Change the string based on a condition
message = "Status is ${var.is_active ? "online" : "offline"}"

# (Advanced) Conditionally include text using if/else directive
greeting = "Hello %{ if var.name != "" }${var.name}%{ else }User%{ endif }"

# Loop through a list to generate a string using "for" directive
ip_list = "Allowed IPs: %{ for ip in var.ip_addresses }${ip}, %{ endfor }"
```

## Terraform Built-in Functions

- Reference: https://developer.hashicorp.com/terraform/language/functions

- Terraform built-in functions are predefined operations embedded directly within the HCL to transform data, manipulate strings, and calculate infrastructure values dynamically.
- You cannot create custom, user-defined functions directly in the template files, but you can test any built-in option instantly using the terraform console command in your terminal.

| Category          | Purpose                                                           | Core Examples                                        |
| ----------------- | ----------------------------------------------------------------- | ---------------------------------------------------- |
| String            | Modify and format textual data                                    | lower(), upper(), join(), split(), replace()         |
| Collection        | Query, merge, or alter lists, maps, and sets                      | length(), lookup(), merge(), flatten(), element()    |
| Numeric           | Perform mathematical calculations                                 | abs(), ceil(), floor(), max(), min()                 |
| Filesystem        | Pull data from local configurations and files                     | file(), filebase64(), templatefile(), dirname()      |
| IP Network        | Calculate subnet address masks and CIDR ranges                    | cidrsubnet(), cidrnetmask(), cidrhost()              |
| Type Conversion   | Safely alter variable primitives into strict data types           | tostring(), tonumber(), toset(), tolist()            |
| Encoding / Crypto | Format JSON/YAML or generate secure checksum cryptographic values | jsonencode(), jsondecode(), base64encode(), sha256() |
| Date and Time     | Inject real-world timestamps or calculate intervals               | timestamp(), timeadd(), formatdate()                 |

### Commonly used built-in Functions

- **format(string_format, unformatted_string)**
  - The format function is used for formatting a number of values according to a specification string.
  - It can be used to build different strings that may be used in conjunction with other variables

  ```bash
  locals {
    string1       = "str1"
    string2       = "str2"
    int1          = 3
    apply_format  = format("This is %s", local.string1)
    apply_format2 = format("%s_%s_%d", local.string1, local.string2, local.int1)
    }

    output "apply_format" {
    value = local.apply_format
    }
    output "apply_format2" {
    value = local.apply_format2
    }
  ```

  - This will result in:

  ```bash
  apply_format  = "This is str1"
  apply_format2 = "str1_str2_3"
  ```

- length(list / string / map)
  - Terraform length function returns the length of a string, list, or map.

  ```bash
  locals {
    list_length   = length([10, 20, 30])
    string_length = length("devops")
  }

  output "lengths" {
    value = format("List length is %d. String length is %d", local.list_length, local.string_length)
  }
  ```

## Meta-Arguments

- `Meta-arguments` are special configuration options in Terraform that change how a resource or module behaves.
- Instead of defining the properties of the infrastructure (like an IP address or size), they control how Terraform creates, scales, and manages the resource itself.

- There are five meta-arguments, as follows:
  1. depends_on
  2. count
  3. for_each
  4. provider
  5. lifecycle
