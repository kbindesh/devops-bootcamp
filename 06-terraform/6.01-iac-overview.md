# Infrastructure-as-Code (IaC) Basics

## IaC Overview

- Infrastructure as Code (IaC) is a DevOps practice where IT infrastructure such as virtual servers, networks, databases, and connection topologies is provisioned and managed using machine-readable configuration files instead of manual interactive tools or physical hardware setup.

- By treating your infrastructure exactly like application software code, you can automate your deployment environments rapidly, consistently, and reliably.

## How IaC works?

- Instead of manually clicking through a cloud console or SSH-ing into servers to configure settings, developers write code defining the desired infrastructure setup.
- This configuration file acts as a blueprint.
- When the IaC config files run through an automation engine, the tool automatically communicates with cloud vendors via APIs to build, modify, or tear down those exact components.

## What are the advantages of IaC?

- Consistency
  - Eliminates configuration drift and human errors caused by manual setup.

- Speed & Efficiency
  - Replaces time-consuming environment builds with a simple, automated script execution.

- Version Control
  - Infrastructure files live inside repositories like GitHub, allowing teams to track changes, review edits, or easily roll back to previous versions.

- Idempotency
  - A core principle ensuring that running the same code multiple times always yields identical results without creating duplicate resources.

  ## Key Approaches to define Infrastructure

| Feature            | _Declarative Approach_                                     | _Imperative Approach_                                           |
| ------------------ | ---------------------------------------------------------- | --------------------------------------------------------------- |
| **Focus**          | Defines what the final state should look like.             | Details how to achieve the setup step-by-step.                  |
| **Management**     | The tool automatically figures out the steps to get there. | The user must execute precise commands in the correct sequence. |
| **State Tracking** | Automatically tracks and updates the current state.        | The user is responsible for managing changes manually.          |
